========================================================
 WOLHUD — КАСТОМНЫЕ FBX-АССЕТЫ
========================================================

Все файлы кладутся в эту папку: public/assets/

Имена файлов ВАЖНЫ (движок ищет именно такие имена):

--------------------------------------------------------
 1) КАРТА
--------------------------------------------------------
  map.fbx      — сама карта (геометрия, в идеале с запечёнными текстурами
                 внутри файла, чтобы не тащить отдельные текстуры).
  map.json     — (НЕОБЯЗАТЕЛЬНО, но рекомендуется) коллизии и точки
                 спавна. Формат ниже.

  Правила экспорта карты:
   * 1 юнит = 1 метр.
   * Запекайте/встраивайте текстуры в FBX (embedded media), иначе они
     потеряются.
   * Карта должна быть в основном «коробочной» (полы, стены, ящики) —
     столкновения считаются по AABB (прямоугольным коробкам) каждой сетки.
   * Пол должен быть на высоте около Y=0, если хотите дефолтные спавны.

  Что будет, если:
   * только map.fbx            → карта видна, коллизии и спавны
                                 генерируются автоматически (по AABB сеток).
   * map.fbx + map.json        → карта видна, коллизии/спавны берутся из
                                 map.json (точно и предсказуемо).
   * нет map.fbx               → встроенная процедурная карта.

--------------------------------------------------------
 2) ИГРОК (модель + анимации в ОДНОМ файле)
--------------------------------------------------------
  player.fbx   — модель игрока со СКЕЛЕТОМ и встроенными анимациями
                 (skin + все клипы в одном FBX).

  Требования:
   * Модель должна быть скелетной (SkinnedMesh) и ориентирована лицом
     в направлении +Z или -Z (движок сам повернёт; если модель смотрит
     не туда — поменяйте ротацию в экспортере).
   * Рост модели автоматически нормализуется под 1.78 м (ноги ставятся
     на землю), масштаб FBX не важен.
   * Анимации должны лежать ВНУТРИ player.fbx как отдельные клипы (takes).

  Как называть анимации (движок ищет по ключевым словам, регистр не важен):

    Состояние      Имя клипа (любое из)
    ---------      -------------------------------
    idle (стоит)    Idle, Idle_01, Stand, Neutral, T-Pose
    walk (ходит)    Walk, Walking
    run  (бежит)    Run, Running, Sprint
    shoot (стреляет) Shoot, Shooting, Fire, Attack
    reload (перезар.) Reload, Reloading
    jump  (прыжок)  Jump, Jumping
    death (смерть)  Death, Die, Dead, Down

  (Подходит стандартный нейминг из Mixamo: "Idle", "Walking", "Running",
   "Shooting", "Reloading", "Death", "Jumping".)

  Если какой-то клип не найден — используется idle, игра не сломается.

  Замечание: модель из player.fbx используется для ДРУГИХ игроков и в
  3D-меню. Для вида «из глаз» остаются процедурные руки с оружием.

--------------------------------------------------------
 3) ФОРМАТ map.json
--------------------------------------------------------
{
  "spawns": [ [-16,0,-16], [16,0,-16], [-16,0,16], [16,0,16] ],
  "colliders": [
    { "p": [0, -0.05, 0], "s": [52, 0.1, 52] },
    { "p": [-10, 1.2, -13], "s": [2, 2.4, 2] }
  ]
}

  * "spawns"    — массив точек [x, y, z] (y — это уровень НОГ, ставьте на
                  верхнюю грань пола).
  * "colliders" — массив коробок: p = центр [cx,cy,cz], s = размер [sx,sy,sz].

  map.json читает И СЕРВЕР (для честного hitscan), И клиенты. Поэтому при
  наличии map.json именно он определяет мир, а не автогенерация.

--------------------------------------------------------
 4) ЛАН (LAN) МУЛЬТИПЛЕЕР
--------------------------------------------------------
  1. На компьютере-сервере:  npm install && npm start
     В консоли появится список адресов, например:
        LAN:     http://192.168.1.42:3000
  2. На других компьютерах в той же сети открой этот адрес в браузере.
  3. Если не подключается — разрешите порт 3000 в брандмауэре сервера.

  Сервер слушает 0.0.0.0:3000, так что любой ПК в локалке может подключиться
  по IP сервера. Порт меняется через переменную PORT=... npm start.
