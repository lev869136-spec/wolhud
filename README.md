# WOLHUD

Мультиплеерный шутер от первого лица в браузере — с 3D-меню в духе CS2 и
чистой low-poly графикой в стиле Standoff 2. Без сборки. Работает «из коробки»
(карта, персонажи и звук генерируются кодом), но умеет принимать **FBX**:
кастомную карту и модели игроков со встроенными анимациями.

## Запуск (LAN-мультиплеер)

```bash
npm install
npm start
```

Сервер слушает `0.0.0.0:3000` и печатает адреса для локальной сети:

```
WOLHUD server (LAN multiplayer)
  local:   http://localhost:3000
  LAN:     http://192.168.1.42:3000
```

Открой `http://localhost:3000` на сервере или `http://<IP-сервера>:3000`
с любого другого ПК в той же сети. Не подключается — разреши порт `3000` в
брандмауэре. Порт меняется через `PORT=8080 npm start`.

## Кастомные FBX-ассеты

Клади файлы в папку `public/assets/`:

| Файл | Что это |
| --- | --- |
| `map.fbx` | карта (1 юнит = 1 метр, текстуры встроить в FBX) |
| `map.json` | *(опционально)* коллизии + точки спавна |
| `player.fbx` | модель игрока: скелет + **все анимации в одном файле** |

Анимации в `player.fbx` называй по ключевым словам (регистр не важен):
`Idle`, `Walk/Walking`, `Run/Running`, `Shoot/Shooting`, `Reload/Reloading`,
`Jump/Jumping`, `Death/Die` — подходит стандартный нейминг Mixamo.

Подробная инструкция (формат `map.json`, правила экспорта, автогенерация
коллизий) — в [`public/assets/README.txt`](public/assets/README.txt).

Всё опционально: нет `map.fbx`/`player.fbx` → используется встроенная
процедурная карта и low-poly бойцы, игра не ломается.

## Структура

```
server/            Node.js: Express (статика) + WebSocket (мультиплеер)
  index.js         HTTP + WS сервер, тик-цикл, печать LAN-адресов
  game.js          комнаты, игроки, авторитетный hitscan, урон/киллы/респаун,
                   мир из map.json или клиентских FBX-коллизий
public/
  index.html       меню + HUD (+ import map для three)
  css/style.css
  assets/          СЮДА класть map.fbx, player.fbx, map.json (см. README.txt)
  js/config.js     общий конфиг (оружие, карта, спавны) — шарится с сервером
  js/main.js       точка входа, рендер-цикл, предзагрузка FBX, состояния
  js/assets.js     загрузка FBX, автогенерация коллизий/спавнов, анимации игрока
  js/menu.js       3D-сцена главного меню (камера вращается вокруг бойца)
  js/game.js       геймплей: контроллер, коллизии, видмодель, HUD, интерполяция
  js/world.js      небо, свет, процедурная карта, персонажи, частицы
  js/weapons.js    low-poly модели оружия
  js/net.js        WebSocket-клиент
  js/audio.js      процедурные звуки (WebAudio)
  js/input.js      клавиатура + мышь + pointer lock
  vendor/          собранный three.js + FBXLoader (+ fflate, SkeletonUtils)
```

## Как это работает

- **Мультиплеер (LAN)**: WebSocket-сервер слушает `0.0.0.0`, держит комнаты
  (до 8 игроков) и рассылает снапшоты 15 раз в секунду. Движение
  клиент-авторитетное, попадания считает сервер (ray vs капсула игрока /
  AABB-мир), поэтому урон, киллы и хедшоты честные.
- **FBX**: `player.fbx` клонируется через `SkeletonUtils` (у каждого игрока
  свой `AnimationMixer`, анимации по ключевым словам). `map.fbx` используется
  как визуал; коллизии берутся из `map.json` или генерируются из AABB сеток,
  спавны — рейкастом по поверхности. Сервер получает тот же мир, что и клиенты.
- **Графика**: `MeshStandardMaterial` с `flatShading` + контурные рёбра дают
  фасеточный «мобильный» вид, градиентное небо, мягкий туман и дрейфующая пыль.
- **3D-меню**: живая сцена — боец на контейнере, вокруг него медленно едет
  камера, как в CS2.
